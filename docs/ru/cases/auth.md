# Авторизация: единый путь через разные продукты

**2022–2024 · OneTwoTrip / iOS**

Развивал вход по телефону и email, повторную авторизацию, magic link и социальные способы входа в Solar.

## Контекст

Авторизация используется в профиле, заказах и покупке, поэтому ошибка здесь влияет сразу на несколько вертикалей. Я работал с переходами между способами входа, неполными контактами и возвратом пользователя в исходный сценарий.

## Мой вклад

- Развивал повторную авторизацию, обработку состояния сессии и обратную связь для пользователя.
- Работал над новым сценарием входа через email/PIN с переключением на телефон, запросом недостающего телефона и продолжением покупки.
- Участвовал в авторизации Solar: magic link, Apple ID и Google ID, обработка входящих ссылок и различий конфигурации продукта.
- Разбирал пограничные состояния: отсутствие интернета, капчу, повторную отправку кода, смену метода входа, клавиатуру, валидацию и регистрацию внутри покупки.
- Добавлял подтверждение удаления аккаунта, обновлял события авторизации и тесты Solar.

## Технологии

Swift, UIKit, Presenter / Interactor / Router, Swinject, REST, Deep Links / Universal Links, WebKit, Apple ID / Google ID integrations, XCUITest.

## Инженерные решения

- Успешная авторизация возвращает управление инициатору — профилю, заказам или покупке. Контекст завершения важнее простого закрытия формы.
- Запоминание устройства не заменяет серверную проверку сессии; в портфолио описан пользовательский сценарий без переноса внутренней схемы токенов.
- Общие состояния входа и возврата к действию согласовываются с особенностями каждого провайдера и конфигурацией продукта.

## Качество и проверки

- Есть отдельная задача UI-теста авторизации Solar и последовательная история исправлений сценариев покупки и входящих ссылок.
- Границы ответственности проверялись по реализации и контрактам модулей.

## Результат и границы

Разные точки входа получили согласованный сценарий авторизации с продолжением пользовательского действия и явной обработкой ошибок.
