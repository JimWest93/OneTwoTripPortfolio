# Общие UI-компоненты и переход на UI 2.0

**2022–2026 · OneTwoTrip / iOS**

Развивал общие стили и компоненты, которые используются несколькими продуктовыми командами.

[Смотреть экраны и состояния](#screens) · [Вся галерея](../gallery.md)

## Контекст

Изменение базового поля ввода или кнопки затрагивает множество экранов. Моя работа включала нормализацию API, миграцию потребителей, поддержку состояний и проверку дизайна на разных размерах устройств.

## Мой вклад

- Упрощал общие стили кнопок, обновлял палитру и переносил приложение на новые стили; удалял неиспользуемые компоненты.
- Разрабатывал новые поля ввода и поля поиска, включая отдельный компактный вариант, состояния ввода, ошибки, блокировку и иконки. Исследовал существующие реализации текстовых полей перед дальнейшим объединением.
- Дорабатывал поля выбора, сегментированный переключатель и floating button; создавал общий виджет профиля.
- Добавлял варианты информационные блоки и нижние панели действий для UI 2.0, поддерживал длинный текст, цены, кнопки и состояния загрузки.
- Обновлял использования общих компонентов в профиле, истории путешествий, формах поиска и тарифах.

## Технологии

Swift, UIKit, SwiftUI interoperability, Props, PinLayout, Design tokens / styles, SnapshotTesting, XCTest, Accessibility identifiers.

| Переход на новые стили | Обновлял кнопки, палитру и использования компонентов в продуктовых модулях. | Последовательная миграция большого приложения. |


## Инженерные решения

- Компонент описывает визуальное состояние через Props, а бизнес-правила остаются у потребителя.
- Новые формы вводились с сохранением совместимости legacy-экранов. Маленькое поле поиска выделялось отдельно, когда его назначение действительно отличалось.
- Для переиспользуемого UI важны не только default-состояния, но и длинные значения, ошибка, disabled, editing, loading и маленькие экраны.

## Качество и проверки

- Отдельные snapshot-задачи для полей ввода; в текущих baselines представлены разные размеры и состояния поля ввода, поля поиска, поля выбора и нижние панели действий.
- При изменении общего компонента учитывал его использования в продуктовых экранах и проверял соответствующие визуальные состояния.

## Результат и границы

Мой вклад — развитие отдельных фундаментальных компонентов и их внедрение в продуктовые сценарии. Архитектура и дизайн-система создавались командой.
