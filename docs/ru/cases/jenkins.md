# Jenkins: диагностируемые сборки и обслуживание CI

**2025–2026 · OneTwoTrip / iOS**

Развивал практические инструменты для dSYM, обслуживания macOS-агентов, информации о сборке и review-процесса.

## Контекст

Для сопровождения iOS-сборок нужны символы диагностики сбоев, доступное место на macOS-агентах и понятная информация об окружении. Я развивал эти инструменты в существующей Jenkins- и Fastlane-инфраструктуре команды.

## Мой вклад

- Создал pipeline загрузки dSYM из кеша выбранного macOS-агента по приложению, версии и номеру сборки. Добавил проверку входных данных и кеша, параллельную отправку и повтор только неуспешных файлов.
- Расширил загрузку dSYM на debug-сборки релизных задач и добавил имя агента в сведения о сборке.
- Добавил pipeline обслуживания CI-агента: ручной запуск, проверка наличия системного cleaner-скрипта, состояние диска до/после и объём освобождённого места.
- Доработал review-процесс: блок о пройденном ревью для перехода к Test ready реализован в Fastlane уведомления о code review.
- Исправлял среду расчёта метрик: закреплённый Ruby, запуск без пользовательских gems, общий post-cleanup.

## Технологии

Jenkins Declarative Pipeline, Groovy, Bash, Ruby / Fastlane, macOS agents, Firebase Crashlytics dSYM, mise, Git.

## Инженерные решения

- Повтор загрузки dSYM ограничен общим timeout job; это не тот же механизм, что ограниченные HTTP-retry в более позднем отправщике метрик.
- Pipeline обслуживания выполняет ручную очистку выбранного агента с проверкой результата по свободному месту.
- Мой вклад сосредоточен на pipeline-оркестрации и интеграции существующих системных инструментов.

## Качество и проверки

- При работе над dSYM и обслуживанием агентов учитывал проверки входных параметров, наличие требуемых файлов и обработку неуспешных операций.
- Для Ruby launcher выполнялись регрессионные проверки конфликтов gems и подключения entry points. Оценка production-надёжности в локальные проверки не входит.

## Результат и границы

Появились самостоятельные инструменты обслуживания и диагностики iOS CI, а информация о сборках стала полезнее для поиска причин сбоев. Экономию времени и изменение доступности CI без измерений не заявляю.
